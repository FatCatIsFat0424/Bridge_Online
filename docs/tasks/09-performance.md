# 09 — 效能優化與功能保留

日期：2026-10-03。範圍：既有帳號、好友、房間與遊戲的效能；不改變資料 schema、API 或遊戲規則。

## 已完成

- [x] 先建立相同資料與操作的 repository / Socket 基準量測。
- [x] 帳號、session、好友與歷史採用按需索引，有限搜尋提早停止。
- [x] 寫入只複製受影響的 collection，保留完整驗證、fsync 與原子替換。
- [x] Runtime 保留失敗回復快照，避免提交前再做一次完整深複製。
- [x] 快照僅傳送操作者與受影響房間，涵蓋舊 / 新房間及多分頁。
- [x] 未改變 runtime 的 resume 不重寫資料，真實附加 / 斷線 / 重連仍保存。
- [x] 前端 route lazy loading、精確 store selectors 與相同快照去重。
- [x] 加入功能等價、授權失敗、寫入失敗與隔離範圍回歸測試。
- [x] 公開可重現 benchmark 命令、測量條件及限制。

## 驗證與結果

三房十二玩家基準中，一次聊天的快照由 12 降到 4，payload 由 13,488 降到 5,200 bytes。
十次未改變的 resume 寫入由 10 降到 0；受影響玩家的完整快照與 callback 內容保留。
索引加速 repository 查詢，JSON 真正寫入仍會驗證及序列化整份資料。

前端登入初始 JS 包含入口、預載及登入路由後，gzip 為 101.64 → 97.45 kB；
不能只比較入口 chunk。相同快照不再通知 store 訂閱者。
詳細資料集、前後測量與限制見[效能 Wiki](../wiki/performance.md)。

功能回歸和瀏覽器流程已驗證。交付前執行 TypeScript、ESLint、完整 Vitest 與正式建置；
最終測試數量由整體交付檢查輸出記錄，避免與後續功能測試混淆。
